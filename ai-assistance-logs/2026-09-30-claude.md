## 14. LLM response

1. **A slim status bar across the bottom of the window,** as in Finder (item count and free space) or Safari. The HIG allows a bottom bar for a small amount of information and controls about the window's content, used sparingly. Our transient status messages and counts ("12 of 2,688 emoji", "Copied 😊") would fit there naturally, which would also free the title area.

## 16. LLM response

It wouldn't clearly violate a HIG rule, but it would go against convention, and I don't know of a mainstream Mac app that uses it for its main window. Ribbons exist on the Mac almost only in cross-platform apps.

**Settings-style tabs on the main window.** As far as I know, the HIG has no rule saying "never do this in a main window". But it only describes the large-icon toolbar of panes in the context of settings windows. For main-window navigation it points to sidebars, tab views and segmented controls. So it isn't a breach, but it would go against convention, with practical costs:

- **It reads as Settings.** People have learned that a row of large icons with tiny labels means a preferences window, so Nice Mail's main window would look like its own Settings.
- **The toolbar can't hold commands.** In that style the pane icons take up the whole toolbar, so Copy, Send and search would all have to move into the content or to bottom bars.
- **Settings windows behave differently.** They usually have a fixed width, resize to fit each pane, and have no ⌘1–⌘4 shortcuts. A main window should resize freely and remember its size.
- **It takes extra work in SwiftUI.** You get this look automatically only inside a `Settings` scene. On a main window you'd have to wrap AppKit's toolbar-style tab view controller.

**Precedent.** Apple's Directory Utility uses toolbar-icon panes in its main window, as far as I recall, and the retired Network Utility used a tab row at the top of its content. Both are small utilities whose windows are essentially settings or diagnostics. I can't think of a well-known app whose main workflow window uses this style, and I haven't checked the latest macOS versions live.

**Ribbons on the Mac.** Mac-native apps generally avoid them, and ribbons appear mostly in cross-platform software:

- **ONLYOFFICE and WPS Office** use Office-like tabbed ribbons on the Mac.
- **LibreOffice** offers an optional tabbed "Notebookbar" layout.
- **Autodesk Fusion** has a tabbed, ribbon-like toolbar.
- **AutoCAD for Mac** is the telling counter-example. Autodesk deliberately swapped the Windows ribbon for a Mac-style palette.

Apple's own answer to the ribbon is in Keynote, Pages and Numbers. They use a toolbar of a few labelled buttons, plus a Format inspector on the right with tabs that change with the selection. The full set of commands lives there and in the menus, not in a ribbon.

**My advice.** I'd keep the segmented tabs, which have clear precedent in Activity Monitor, Clock and Calendar.
